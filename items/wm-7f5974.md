Samuel's PR https://github.com/edgefocus/efp/pull/6424 (DOPS-694). Reviewed 2026-08-21 — the fix is right and CI is green.

Root cause verified: northpond's caller cut over to `/api/v2/...` on **2026-01-16** (2026-01-15 is the last flat day; every day since is `v2/` only). `keygen.compose_s3_prefix` inserts `v{N}/` between the date and the category for api_version >= 2, and api_version comes off the request URL, so the layout is caller-driven. The checker hand-built the flat path, so northpond has had **no working last-order freshness alarm since 2026-01-16** — the empty branch `continue`s before the staleness check.

Two changes to request:
1. Concatenate both layouts instead of returning the first non-empty. api_version is per-request, so a channel can serve v1 and v2 on the same date; flat-first would then hide newer v2 keys and fire a false "Last order > N minutes ago". Northpond's own cutover was clean, so it isn't biting today.
2. `delete_error("Missing Endpoint Transactions")` does not exist anywhere in the repo, and the subject is not channel-scoped (unlike the threshold error). After merge, EFP-ERRORS-YQ stops receiving events but stays unresolved forever. Fix: `subject=f"Missing Endpoint Transactions for {channel}"` + `delete_error` on the success path.

Lower priority: v2 is hardcoded while keygen/ingest handle `v{N}` generically (test_keygen already asserts a v3 path) — `s3.list_single_level(<date>/)` is one delimiter listing that discovers the layout without a key sweep.

Follow-up either way: resolve EFP-ERRORS-YQ in Sentry by hand after the next `Cron Scripts - Admin` Jenkins deploy.
